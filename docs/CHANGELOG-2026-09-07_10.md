## 一、新增「改动审查」插件（change-review）

- **插件落地**（`ce0a772`）：Agent 每次改动文件（write_file/edit_file/apply_patch/delete_file）后可查看行级 diff 并一键撤销；多文件分别列出、可单独或全部撤销。
- **绑定可见过程**（`47c0937`）：审查记录关联到具体一轮执行过程，避免串到其他轮次。
- **跟踪净变更**（`1de4d0f`）：按执行工作区计算净变化（多次写入合并为最终 diff）。
- **存储加固 + 基准**（`eb4506d`）：审查存储健壮性提升，新增性能基准。

## 二、扩展与插件系统

- **按目录信任内置插件**（`fe2f1da`）：`plugins/host.py` 的硬编码白名单（`_BUNDLED_TRUSTED_HOST_PLUGIN_IDS`）改为按 `plugins/` 目录内容动态识别——放入插件包即自动识别。

## 三、会话生命周期与运行态

- **草稿优先新会话**（`a4eb156`）：点"新会话"只开本地草稿页（不建目录、不扫描），首次发送才创建真实会话；输入内容不中途消失；新会话加入保护区防被旧快照删除；后端缓存"旧值返回 + 后台刷新"消除 6–10s 阻塞。
- **真实运行终态**（`2e18430`）：`final` 只表示正文原子落盘；运行进入 finalizing 态；`history_snapshot` 携带 `run_id` 身份，旧快照/轮询/残留 SSE 连接不能再把已结束任务重新置为活跃（消除"长时间黄点"误报）。
- **流保活**（`6a13c19`）：对账、断连与陈旧快照场景下保持运行中流存活。
- **新会话创建响应**（`0b3490b`）：创建新会话不再阻塞。

## 四、LLM 传输与错误处理

- **自定义请求头**（`106e73f`）：模型 profile 可声明 `headers`（如 OpenCode `x-opencode-*`），进 provider 缓存键。
- **候选失败原因保留**（`6650fe8`）：`CandidateFailureSnapshot` 保存原始异常（提取 HTTP 状态、免 traceback），错误原因不再被覆盖；日志文本脱敏（Authorization/Bearer、`sk-`/`tp-`、查询密钥）。
- **恢复首 token 竞速**（`edafdda`）：执行器门面重新启用首 token hedge。
